# Project: OWASP MASVS Checklist Integration for MobSF\n\n**Problem Statement:**\nThe current scanning capabilities, while strong in technical vulnerabilities, lack a standardized, comprehensive compliance checklist against industry standards like OWASP MASVS. The manual inclusion of this checklist creates complexity in maintaining the scan process, which is prone to missed checks or inconsistent reporting.\n\n**Goal:**\nAutomate the integration of the OWASP MASVS checklist, making it a standardized, first-class citizen in the MobSF scanning results.\n\n**Approach (Modular Enhancement):**\nWe will adopt a pattern of **Separation of Concerns**, minimizing changes to existing execution points while maximizing the reusability and testability of the new checker.\n\n**Critical Files to Modify/Create:**\n1. `mobsf/DynamicAnalyzer/checks/masvs_checker.py` (NEW)\n   - **Purpose:** Isolates the entire MASVS logic. This module reads the PDF/checklist structure (or a derived internal representation) and provides a method to evaluate the analyzed context against all defined MASVS controls. This is the core business logic.\n   - **Input:** `AnalysisContext` object containing gathered data from existing scanners (e.g., memory dumps, API responses, runtime variables, or the analyzed state).\n   - **Output:** Structured finding set containing `(control_id, status: PASS|FAIL|N/A, evidence_field, severity)`.\n\n2. `mobsf/DynamicAnalyzer/models.py` (MODIFY)\n   - **Goal:** Extend the data structure to report compliance status.\n   - **Changes:** Add fields to the primary result model (e.g., `ScanResult` or a nested `ComplianceReport` object) to hold the MASVS findings list and a summary status.\n\n3. `mobsf/DynamicAnalyzer/admin.py` (MODIFY)\n   - **Goal:** Update the execution pipeline.\n   - **Changes:** Locate the main scan function (e.g., `run_scan()` or similar) and add a call sequence to initialize and run the `MASVSChecker`. This updated orchestrator ensures the new module runs at the appropriate point in the scan life cycle (e.g., after all other checks are complete, or integrated in parallel if the checks are designed to run concurrently).\n\n**Implementation Plan (Step-by-Step):**\n1. **[Develop]** Create `mobsf/DynamicAnalyzer/checks/masvs_checker.py`. This involves parsing the PDF or mapping its requirements to Python logic and developing the `check()` method.\n2. **[Update]** Modify `mobsf/DynamicAnalyzer/models.py`. Add the `masvs_findings` list and related scoring logic to the result container.\n3. **[Update]** Modify `mobsf/DynamicAnalyzer/admin.py`. Inject the call to `MASVSChecker.run()` into the `run_scan()` function, ensuring the context passed to the checker is complete.\n\n**Verification Strategy:**\n1. **Unit Tests:** Write dedicated unit tests for `masvs_checker.py` to ensure each rule is tested in isolation against mock `AnalysisContext`.\n2. **Integration Test:** Run the full scan using `mobsf/DynamicAnalyzer/admin.py` (or its related entry point) and use `Read` or `Test` tools to assert that:\n   a. The `MASVSChecker` is correctly invoked.\n   b. The final output object contains the `masvs_findings` field with accurate data.\n   c. The console/API output reflects the compliance score derived from the new model.\n\n**Dependencies/Risks:**\n- **Dependency:** The success heavily relies on being able to accurately parse the `OWASP_MASVS.pdf` into machine-readable rules.\n- **Risk:** The `AnalysisContext` object might need refactoring if the MASVS requirements pull data sources not currently accessible by the existing scanners.\n\n**Conclusion:** The plan is solid, modular, and follows best practices for extending a large, complex system.
